АРХІТЕКТУРА ТА АРХІТЕКТУРНІ РІШЕННЯ - TechDesk (Mini IT Helpdesk)

Єдине джерело істини для моделі даних, переходів і PATCH: docs/requirements.md.

1. Схема компонентів

[REST API Client / Swagger UI]
              |
              v
1. API Layer (routes + schemas)
   HTTP-маршрути, Pydantic-валідація входу/виходу, мапінг помилок у 404/409/422/503
              |
              v
2. Service Layer (service) ------------------> [AI Classifier Adapter]
   Бізнес-правила, матриця 3x3, атомарний       (read-only рекомендації без
   PATCH, фільтрація AND                         автозміни тікетів)
              |
              v
3. Persistence Layer (database)
   SQLite-запити, транзакції, FK, довідник users
              |
              v
   [SQLite: techdesk.db / :memory:]

Розмежування відповідальності:
| Модуль | Відповідальність |
|--------|------------------|
| schemas | Перевірка форми JSON, типів, довжин, strip(), enum, extra="forbid", серіалізація. |
| routes | Приймання HTTP-запитів, виклик service, перетворення винятків на 404/409/422/503. |
| service | Матриця переходів 3x3, заборона редагування CLOSED, атомарний PATCH, фільтрація AND, виклик AI-адаптера (ЛР4). |
| database | Ініціалізація таблиць і users, SQL-операції, сортування ORDER BY created_at ASC, id ASC, транзакції. |

2. Модель сутностей

User: id (PK), name.
Ticket: id (PK), title, description, status, priority, assignee_id (FK -> User.id, nullable), created_at.
Comment: id (PK), ticket_id (FK -> Ticket.id), author_id (FK -> User.id), body, created_at.

Зв'язки:
- User (1) --- (0..N) Ticket (виконавець)
- Ticket (1) --- (0..N) Comment
- User (1) --- (0..N) Comment (автор)

3. Архітектурні рішення

ADR-01: SQLite та локальний запуск без контейнерів
- Контекст: локальний сервіс для навчального обсягу даних, потрібне збереження між перезапусками та ізольовані тести (FR-07, NFR-01, NFR-02).
- Варіанти: 1) SQLite; 2) PostgreSQL у Docker; 3) зберігання в пам'яті.
- Обране рішення: SQLite з локальним запуском через uvicorn.
- Причина: вбудований у Python, не потребує Docker, підтримує ACID і FK, дозволяє легко створювати ізольовану БД для pytest. Зберігання в пам'яті порушує FR-07.
- Наслідки та обмеження: не розраховано на високу конкурентність запису та кластеризацію, що не потрібно в межах проєкту.

ADR-02: Відокремлення AI-компонента від бізнес-логіки
- Контекст: у ЛР4 додається AI-рекомендація (FR-08), при цьому облік тікетів має працювати без LLM (NFR-04), а тікет не змінюється автоматично.
- Варіанти: 1) автозаповнення полів при POST /tickets через LLM; 2) окремий read-only адаптер AIClassifierAdapter.
- Обране рішення: окремий read-only адаптер із виділеним маршрутом рекомендацій.
- Причина: гарантує виконання FR-08 і NFR-04; збій або помилка LLM не блокує роботу сервісу і не псує збережені дані.
- Наслідки та обмеження: інженер застосовує рекомендацію вручну через PATCH /tickets/{id}, що забезпечує контроль людини і просте тестування з моками.
